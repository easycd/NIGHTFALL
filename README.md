# NIGHTFALL — 마지막 불빛

Dead by Daylight에서 영감을 받은 오리지널 2D 브라우저 비대칭 멀티플레이 프로토타입입니다. 상표·그래픽·캐릭터 에셋을 사용하지 않습니다.

게임 소스 저장소: https://github.com/easycd/NIGHTFALL

공개 게임 주소: https://omok-sai.onrender.com/dbd/

## 실행

Node.js 20 이상에서 `npm ci` → `npm start` 후 http://localhost:3002/dbd/ 를 엽니다. 서로 다른 브라우저 탭에서 3명 이상 접속해 시작할 수 있습니다. 방장은 기본 살인마이며 대기실에서 역할을 바꿀 수 있습니다. 초대 링크를 복사해 다른 플레이어에게 전달합니다. 실제 인터넷 플레이는 Render 배포가 필요합니다.

## 게임 규칙

- 기본 6명(살인마 1 + 도망자 5), 최소 3명, 현재 최대 16명. 시작 시 살인마 정확히 1명, 도망자 최소 2명을 검증합니다.
- WASD 이동, SPACE 상호작용. 상호작용을 한 번 누르는 동작과 길게 누르는 동작을 구분합니다.
- 3200×2400 맵, 반대편에 생성되는 탈출구 2개. 벽 충돌, 풀숲, 캐비넷, 1회용 파레트가 있습니다.
- 도망자 속도 170px/s, 살인마 255px/s. 운반 중 살인마 속도는 20% 감소합니다.
- 원형 시야 반지름 도망자 210px, 살인마 525px(2.5배). 서버가 시야 밖 플레이어 좌표를 숨깁니다. 풀숲의 도망자는 살인마가 65px 이내로 접근할 때 보이며 캐비넷 안에서는 보이지 않습니다. 벽 너머도 원형 시야 안이면 보입니다.
- 충돌한 도망자는 기절. 살인마가 SPACE로 들어 올려 빈 감옥 근처에서 SPACE를 다시 눌러 가둡니다.
- 구출은 동료가 SPACE를 연속 5초 누릅니다. 중단 시 구출 게이지가 초기화됩니다. 구출 후 3초간 재기절 면역.
- 감옥에 두 번째 갇히면 탈락. 탈락·탈출 후 SPACE로 살아 있는 플레이어를 관전합니다.
- 파레트를 내려 근처(130px 이내)의 살인마에게 2초 스턴. 내려진 파레트는 도망자만 통과하며 살인마는 SPACE를 1.5초 눌러 부숩니다.
- 발전기 5개를 각각 60초 수리. 수리 중단 시 진행도가 유지됩니다. 협동 수리는 속도를 가속하지 않습니다. 모두 가동되면 양쪽 출구가 열리고 접근하면 탈출합니다.
- 도망자가 모두 탈출하거나 탈락하면 종료. 1명 이상 탈출하면 도망자 측 승리, 전원 탈락하면 살인마 승리.
- 재접속 유예 30초. 방 나가기는 즉시 탈락으로 처리합니다. 게임 진행 중 신규 참가는 제한됩니다.

## 조정

`config.js`에서 속도, 시야, 정원, 수리 시간, 스턴, 구출 시간을 조정합니다. 맵 배치는 `game.js`의 `createMap()`에서 변경합니다. 탈출구 방향은 매 판 결정됩니다.

## admin 디버깅

플레이어 이름을 정확히 `admin`으로 입력하고 방을 만들거나 참가하면 디버깅 도구가 나타납니다. 대기실에서는 혼자서도 맵을 살펴볼 수 있으며, 실제 게임 시작에는 기존 최소 인원이 필요합니다.

- `T`: 전체 맵 / 일반 시야 전환. 전체 맵에서는 안개가 사라지고 모든 플레이어 및 숨은 상태를 확인할 수 있습니다.
- 마우스 휠 / 드래그: 전체 맵 확대·축소 / 카메라 이동. '맵에 맞추기'로 초기화합니다.
- 오브젝트 클릭: ID, 좌표, 크기, 발전기 수리 진행·작업자, 감옥 수감자·구출 진행, 캐비넷 점유자, 파레트 상태·파괴 진행, 출구 개방 상태, 플레이어 감금 횟수·스턴·면역·운반 대상을 확인합니다.
- `B`: 충돌·상호작용 영역 표시. `O`: 오브젝트 ID 및 플레이어 상태 표시. `I`: 디버깅 패널 접기 / 열기.
- 패널에서 FPS, 서버 왕복 지연시간(PING), 서버 tick 설정, 맵 seed, 좌표, 이동속도, 시야 반지름, 오브젝트 개수와 발전기 진행도를 확인합니다.
- '상태 JSON 보기 / 저장': 전체 맵의 현재 상태를 화면에서 확인·복사하거나 로컬 JSON 파일로 저장합니다.

디버깅은 확인 기능만 제공하며 발전기·플레이어·게임 규칙을 수정하지 않습니다. 일반 플레이어에게는 전체 좌표·캐비넷 점유자가 전송되지 않고 디버깅 요청도 서버에서 거부합니다. 이름 기반 모드이므로 누구나 `admin`을 입력해 사용할 수 있습니다. 계정 관리자 권한이나 인증 기능은 아닙니다.

## 기존 오목 Render 서버와 함께 실행

기존 프로젝트: `C:/Project/Concave`, 저장소: https://github.com/easycd/Concave_Game

동기화: 이 폴더에서 `node scripts/integrate-concave.mjs C:/Project/Concave`.

기존 오목 HTTP 서버와 Socket.IO 인스턴스에 `/nightfall` 네임스페이스를 추가합니다. 추가 서버/포트는 필요 없습니다. 오목은 `/`, NIGHTFALL은 `/dbd/`, 상태 확인은 `/dbd/api/health`입니다. 통합 파일은 오목 저장소의 `nightfall/`에 복사되고 `server/index.ts`에서 연결됩니다.

Render 서비스 `omok-sai`에는 자동 배포가 꺼져 있습니다. 오목 저장소 변경을 GitHub에 반영하고 기존 Render 서비스를 수동 재배포해야 https://omok-sai.onrender.com/dbd/ 에서 접근할 수 있습니다. 재배포하면 진행 중인 두 게임의 메모리 방이 초기화됩니다.

## 검증

`npm test`: 실제 소켓의 방 생성/참가, 입력 동기화, 방 분리, 재접속, 서버 시야 제한 및 게임 규칙 검증.

`npm run check`: JavaScript 구문 검사.

오목 프로젝트에서 `npm test`와 `npm run build`: 기존 오목 회귀 테스트와 통합 빌드.

현재 상태는 첫 플레이 가능한 프로토타입입니다. 방은 메모리에 보관하므로 단일 서버 인스턴스로 실행합니다. 모바일 화면은 대응하지만 조작은 키보드 기준입니다. 원형 시야는 벽에 가려지지 않으며 장애물 경계 충돌을 계산합니다. 사운드, 봇, 매치메이킹, 영구 계정, 안티치트 강화는 포함하지 않았습니다.
